# 에코소트 전처리 상세 설계

이 문서는 「에코소트 데이터·전처리 계획」의 3장(실시간 전처리)과 4장(학습용 처리)을 에코소트 환경에 맞춰 자세히 풀어 쓴 설계서입니다. 각 단계마다 **어떤 기법을 쓰는지, 왜 쓰는지, 왜 그 순서인지**를 적었습니다.

현장 조사 전 초기안이므로, 조사 결과에 따라 바뀌는 부분은 체크리스트 항목 번호(예: D-03)로 표시했습니다.

---

## 1. 내 환경과 전처리에 주는 의미

전처리는 "환경이 만드는 문제"를 해결하는 작업입니다. 그래서 먼저 에코소트 환경의 특징이 어떤 문제를 만드는지 정리합니다.

| 환경 특징 | 만들어지는 문제 | 전처리로 하는 일 |
|---|---|---|
| 흰색 아크릴 라이트박스, LED 확산 조명 (외부광 차단) | 조명이 거의 고정 → 대신 흰 종이·투명 물체가 배경과 구분이 잘 안 됨 | 밝기 정규화는 최소화, 물체 분리(마스크)에 집중 |
| 배경이 항상 같은 빈 라이트박스 | 배경 이미지를 미리 저장할 수 있음 | 저장 배경과의 차분으로 물체 위치를 찾음 |
| 흰 배경 = 균일한 반사판 | 빈 배경 자체가 조명 분포 측정판 역할을 함 | 별도 기준판 없이 배경으로 조명 불균일·색 보정값을 계산 |
| USB 웹캠 (C920급), 넓은 화각 약 78° | 가장자리 원근·렌즈 왜곡, 자동 노출·초점 변동, MJPEG 압축 | 카메라 설정 고정, 필요 시 렌즈 왜곡 보정 |
| 1080p 해상도, Jetson CPU | 원본 전체 처리는 느림 | 위치 찾기는 저해상도, 인식용 크롭은 원본 해상도 |
| 한 번에 1개 품목, 위에서 촬영 | 물체가 아무 방향으로나 놓임, 크기 편차 큼 | ROI 크롭 + 정사각형 패딩으로 크기·위치 정규화 |
| 투명 페트·컵, 캔·은박 반사 (B-03, D-03) | 차분 마스크 실패, 하이라이트 포화 | 색차 기반 차분 + 엣지 기반 대체 마스크, 노출 낮춤 |
| 구김·라벨·오염 (B-04~B-06) | 같은 클래스 안에서 외형 편차가 큼 | 실시간에서는 건드리지 않고 학습 증강으로 대응 |
| 판정 0.5초, 전처리 예산 약 50ms | 무거운 기법(디노이징, 인페인팅) 사용 불가 | 단계별 시간 예산을 정하고 미리 계산할 수 있는 것은 부팅 시 계산 |
| 공개 데이터로 사전학습 | 공개 데이터와 배경·조명이 다름 | 학습 데이터에도 같은 전처리를 적용하고, 배경 합성으로 분포를 맞춤 |

## 2. 전처리 순서를 정하는 6가지 원칙

아래 원칙이 이 문서의 모든 순서 결정의 근거입니다. 각 단계 설명에서 원칙 번호(P1~P6)로 다시 언급합니다.

| 원칙 | 내용 | 이유 |
|---|---|---|
| **P1. 싼 검사를 먼저** | 노출 불량, 흔들림 같은 촬영 실패는 가장 먼저 검사한다 | 실패한 이미지에 연산을 쓰지 않고, 재촬영할 시간을 남긴다 |
| **P2. 찾기는 저해상도, 인식은 고해상도** | 물체 위치는 1/4 축소 이미지로 찾고, 분류용 이미지는 원본에서 잘라낸다 | 위치 찾기에는 세부 질감이 필요 없지만, 코팅 종이·플라스틱 구분에는 원본 질감이 필요하다 |
| **P3. 픽셀 단위 보정은 크롭 후에** | 색 보정, 조명 보정은 잘라낸 영역에만 적용한다 | 결과는 같고 처리할 픽셀 수만 줄어든다 (1080p 대비 약 1/5~1/10) |
| **P4. 비교 대상은 같은 처리를 거친다** | 배경 차분 전에 하는 처리(축소, 블러, 색공간 변환)는 저장 배경에도 똑같이 한다 | 처리 방식이 다르면 물체가 없어도 차이가 생긴다 |
| **P5. 학습과 추론은 같은 함수** | 학습 데이터와 실시간 입력은 같은 코드로 전처리한다 | 학습-추론 불일치(train-serve skew)는 정확도 하락의 가장 흔한 원인이다 |
| **P6. 판정에 쓰이는 정보는 보존** | 색, 광택, 투명도는 클래스 구분의 단서이므로 지우지 않고, 잡음만 제거한다 | 투명 페트와 유색 플라스틱, 코팅 종이컵과 플라스틱 컵을 구분하는 단서가 색과 광택이다 |

## 3. 0단계: 전처리 전에 하드웨어로 해결할 것

소프트웨어로 고치는 것보다 촬영 단계에서 막는 것이 빠르고 정확합니다. 아래 설정은 전처리가 아니라 **전처리가 가정하는 조건**입니다.

| 설정 | 값 | 이유 |
|---|---|---|
| 자동 노출 | 끔 (수동 고정) | 물체가 들어오면 자동 노출이 밝기를 바꿔 배경 차분이 무너진다 |
| 노출 기준 | 빈 배경 밝기가 200~220 (8비트) | 255에 닿지 않게 여유를 둬야 캔·은박 하이라이트가 덜 포화된다 (D-03) |
| 자동 화이트밸런스 | 끔 (수동 고정) | 물체 색에 따라 화이트밸런스가 바뀌면 색 단서가 흔들린다 |
| 자동 초점 | 끔, 바닥 높이에 고정 | 투입마다 초점이 흔들리면 흐린 이미지가 생긴다 |
| 전원 주파수(깜빡임 방지) | 60Hz | 국내 전원 기준. LED를 PWM으로 조광하면 줄무늬가 생길 수 있다 |
| 영상 포맷 | MJPG 1920×1080 30fps | C920급은 비압축(YUYV) 1080p가 약 5fps라 지연이 크다. 압축 잡음은 E8 실험으로 확인 |
| 투입구 차광 | 고무 커튼 또는 덮개 (A-02 결과로 결정) | 외부광이 들어오면 배경이 매번 달라진다 |
| 재부팅 시 설정 | 부팅 스크립트로 자동 재적용 (D-07) | 웹캠은 재연결 시 기본값으로 돌아가는 경우가 많다 |

## 4. 부팅 시 캘리브레이션 (한 번만 계산)

실시간 처리를 빠르게 하는 핵심은 **반복되는 계산을 부팅 시 미리 해 두는 것**입니다. 빈 라이트박스 상태에서 다음을 계산해 메모리에 둡니다.

| 계산 대상 | 방법 | 쓰이는 곳 | 이유 |
|---|---|---|---|
| 기준 배경 | 빈 라이트박스 10프레임 평균 | 배경 차분 | 1장만 쓰면 센서 잡음이 그대로 남아 차분 결과가 지저분해진다. 10장 평균은 잡음을 약 1/3로 줄인다 |
| 축소 배경 (Lab) | 기준 배경을 1/4 축소 → 3×3 가우시안 → Lab 변환 | 배경 차분 | P4: 실시간 입력과 같은 처리를 미리 해 둔다 |
| 배경 엣지 맵 | 축소 배경 회색조의 Sobel 기울기 크기 | 투명 물체 대체 마스크 | 배경에 원래 있던 엣지(모서리, 이음새)를 빼기 위함 |
| 조명·색 보정 이득 맵 | 기준 배경을 큰 가우시안(σ=25)으로 흐린 뒤, 채널별로 `목표값 ÷ 배경값` | 색 보정 (크롭 후) | 흰 배경이 곧 조명 분포이므로, 이 이득을 곱하면 조명 불균일(비네팅)과 색 틀어짐이 한 번에 보정된다 |
| 렌즈 왜곡 맵 (조건부) | 체커보드 캘리브레이션 1회 → remap 맵 저장 | 크롭 영역 왜곡 보정 | 가장자리 왜곡이 2% 이상일 때만 사용 (D-05) |
| 배경 평균색 | 보정 후 배경의 평균 BGR | 정사각형 패딩 색 | 패딩 영역이 실제 배경처럼 보여야 모델이 경계에 반응하지 않는다 |

**이득 맵에서 큰 가우시안을 쓰는 이유.** 배경을 그대로 나누면 아크릴 위의 먼지나 긁힘까지 보정값에 들어가, 물체 위에 먼지 무늬가 찍힙니다. 크게 흐리면 천천히 변하는 조명 분포만 남습니다.

**목표값을 235로 두는 이유.** 255로 맞추면 배경보다 밝은 하이라이트가 모두 잘립니다. 235는 하이라이트를 위한 여유 공간입니다.

**주의.** 아크릴이 완전한 무채색이 아닐 수 있으므로, 설치 시 한 번은 회색 기준판(그레이 카드)으로 보정 결과가 무채색이 되는지 확인합니다.

## 5. 실시간 전처리 단계별 설계

### 5-1. 전체 흐름

| 순서 | 단계 | 해상도 | 예상 시간 | 원칙 |
|---|---|---|---|---|
| S0 | 정지 감지 후 촬영 | 축소 | 대기 시간에 포함 | P1 |
| S1 | 축소 (1/4) | 원본 → 480×270 | 1.0ms | P2 |
| S2 | 노출 검사 | 축소 | 0.3ms | P1 |
| S3 | 블러 + Lab 변환 | 축소 | 0.8ms | P4, P6 |
| S4 | 가중 색차 배경 차분 | 축소 | 0.5ms | P4, P6 |
| S5 | 이진화 | 축소 | 0.2ms | |
| S6 | 모폴로지 (열림 → 닫힘) | 축소 | 0.5ms | |
| S7 | 컨투어 선택·개수 판정 | 축소 | 0.3ms | |
| S8 | (조건부) 투명 물체 대체 마스크 | 축소 | 1.5ms | P6 |
| S9 | 박스 확대·여백 | 좌표 계산 | 0.1ms | P2 |

시간은 Jetson Orin Nano CPU 기준 추정치이며, 2주차에 실측(H-03)으로 확인합니다. 예산 50ms 대비 여유가 크므로, 실측이 추정의 3배가 나와도 예산 안에 들어옵니다.

### 5-2. 단계별 상세

#### S0. 정지 감지 후 촬영

- **기법:** 투입 감지 후 연속 프레임을 아주 작게(160×90) 줄여 비교하고, 두 프레임의 평균 차이가 임계값 아래로 내려가면 그 프레임을 사용합니다. 최대 대기 0.3초.
- **적용 이유:** 고정 0.3초 대기는 물체가 빨리 멈춘 경우 시간을 낭비하고, 늦게 멈춘 경우(굴러가는 캔) 흔들린 이미지를 찍습니다. 실제 정지 시점을 보고 찍으면 두 문제가 함께 해결됩니다.
- **순서 근거:** 모든 처리는 좋은 원본에서 시작해야 합니다 (P1). 흔들린 이미지는 뒤에서 어떤 처리를 해도 복구되지 않습니다.
- **초기 파라미터:** 평균 절대차 < 2 (8비트), 연속 2프레임 만족 시 촬영.
- **실패 시:** 0.3초가 지나도 정지하지 않으면 마지막 프레임을 쓰고, S11 흐림 검사에서 다시 걸러냅니다.
- **주의:** 웹캠 버퍼에 이전 프레임이 남아 있으면 정지 판단이 틀립니다. 버퍼 크기를 1로 두고, 투입 감지 직후 버퍼를 한 번 비웁니다 (H-01).

#### S1. 축소 (1/4)

- **기법:** INTER_AREA 보간으로 1920×1080 → 480×270.
- **적용 이유:** 물체 위치를 찾는 데는 세부 질감이 필요 없습니다. 픽셀 수가 1/16로 줄어 이후 단계(S2~S8)가 빨라집니다.
- **순서 근거:** 위치 찾기 단계의 맨 앞에 둬야 이후 모든 마스크 연산이 작은 이미지에서 이뤄집니다 (P2).
- **INTER_AREA를 쓰는 이유:** 여러 픽셀을 평균하므로 센서 잡음을 줄이는 효과도 있습니다. 축소에서는 가장 정확한 보간법입니다.

#### S2. 노출 검사

- **기법:** 축소 이미지에서 평균 밝기와 포화 픽셀(250 이상) 비율을 계산합니다.
- **적용 이유:** 조명 고장, 외부광 유입, 큰 하이라이트를 조기에 발견합니다.
- **순서 근거:** 계산이 가장 싸고, 실패하면 재촬영해야 하므로 최대한 앞에 둡니다 (P1). 축소 이미지에서 하는 이유는 전체 밝기 판단에는 해상도가 필요 없기 때문입니다.
- **초기 파라미터:** 평균 밝기가 기준 배경 대비 ±25% 벗어나면 조명 이상, 포화 비율 > 5%면 하이라이트 과다.
- **실패 시:** 조명 이상은 '확인 필요' + 텔레그램 알림. 하이라이트 과다는 판정은 진행하되 로그에 표시해 D-03 대응(노출 하향, 편광 필름)의 근거로 씁니다.

#### S3. 블러 + Lab 변환

- **기법:** 3×3 가우시안 블러 후 BGR → Lab 변환.
- **블러를 쓰는 이유:** MJPEG 압축 블록 잡음과 센서 잡음이 이진화 후 점 잡음으로 남는 것을 줄입니다. 3×3은 물체 경계를 거의 흐리지 않는 최소 크기입니다.
- **Lab을 쓰는 이유:** Lab은 밝기(L)와 색(a, b)을 분리합니다. 그림자는 주로 밝기만 낮추고 색은 거의 바꾸지 않으므로, 밝기와 색 차이를 따로 다뤄야 그림자를 물체로 오인하지 않습니다. BGR에서는 그림자와 물체가 섞여서 구분이 어렵습니다.
- **순서 근거:** 배경 차분 직전에 두며, 저장 배경에도 같은 블러와 변환을 미리 적용해 둡니다 (P4).

#### S4. 가중 색차 배경 차분

- **기법:** 저장 배경(Lab)과의 채널별 절대차를 구하고, `차이 = max(0.5 × |ΔL|, |Δa|, |Δb|)`로 합칩니다.
- **적용 이유:** 배경이 항상 같으므로, 학습이 필요 없는 가장 빠르고 확실한 물체 분리 방법입니다.
- **밝기에 0.5 가중치를 주는 이유:** 그림자는 밝기 차이만 크고 색 차이는 작습니다. 밝기 차이를 절반으로 줄이면 그림자는 임계값 아래로 떨어지고, 색이 있는 물체는 색 차이로 잡힙니다 (D-02).
- **최댓값을 쓰는 이유:** 합이나 평균을 쓰면 한 채널에서만 차이가 나는 물체(예: 흰 배경 위 연한 노란 종이)의 신호가 희석됩니다.
- **MOG2를 쓰지 않는 이유:** MOG2는 연속 영상에서 배경을 학습하는 방식이라, 한 장만 찍는 에코소트에서는 저장 배경과의 단순 차분이 더 빠르고 예측 가능합니다. 배경 변화는 7장의 배경 유지 관리로 따로 처리합니다.
- **한계:** 흰 종이와 투명 물체는 밝기·색 차이가 모두 작아 이 단계에서 일부만 잡힙니다. S6의 닫힘 연산과 S8의 대체 마스크가 이를 보완합니다.

#### S5. 이진화

- **기법:** 고정 임계값으로 이진화합니다.
- **초기 파라미터:** 20 (E1에서 12 / 20 / 30 비교).
- **오츠(Otsu) 자동 임계값을 쓰지 않는 이유:** 오츠는 히스토그램이 두 덩어리로 나뉜다고 가정합니다. 물체가 작거나 배경과 비슷하면 엉뚱한 임계값이 나와 결과가 매번 달라집니다. 조명이 고정된 환경에서는 고정값이 더 안정적입니다.

#### S6. 모폴로지 (열림 → 닫힘)

- **기법:** 3×3 열림 연산 후 7×7 닫힘 연산 (축소 해상도 기준, 원본으로는 약 12×12와 28×28).
- **열림의 역할:** 먼지, 압축 잡음 같은 작은 점을 지웁니다 (A-05).
- **닫힘의 역할:** 물체 안쪽의 구멍을 메웁니다. 투명 페트병은 몸통 가운데가 배경과 비슷해 마스크가 고리 모양으로 끊기는데, 닫힘이 이를 하나로 이어 줍니다.
- **열림을 먼저 하는 이유:** 닫힘을 먼저 하면 근처의 잡음 점들이 서로 이어지거나 물체에 붙어서 커진 뒤 지워지지 않습니다. 잡음을 먼저 지우고 물체를 메워야 합니다.
- **커널 크기 조정:** 바닥 먼지가 많으면 열림을 5×5로 (A-05), 투명 물체가 많으면 닫힘을 9×9로 (B-03) 키웁니다.

#### S7. 컨투어 선택·개수 판정

- **기법:** 외곽 컨투어를 찾고, 화면 면적의 0.5% 미만은 버린 뒤 남은 개수를 셉니다.
- **판정 규칙:**
  - 0개 → S8 대체 마스크로 이동
  - 1개 → 정상 진행
  - 2개 이상이고 두 번째가 첫 번째 면적의 30% 이상 → '확인 필요' (여러 개 동시 투입, C-03)
  - 2개 이상이지만 두 번째가 작음 → 가장 큰 것만 사용 (뚜껑이나 라벨 조각으로 판단)
- **순서 근거:** 모폴로지로 조각이 정리된 다음에 세야 한 물체가 여러 개로 세어지지 않습니다.

#### S8. (조건부) 투명 물체 대체 마스크

- **실행 조건:** 투입 센서는 반응했는데 S7에서 유효한 컨투어가 0개이거나, 최대 컨투어가 화면의 2% 미만일 때.
- **기법:** 축소 회색조 이미지의 Sobel 기울기 크기에서 배경 엣지 맵을 빼고, 이진화 → 9×9 닫힘 → 컨투어.
- **적용 이유:** 투명 물체는 색과 밝기는 배경과 비슷하지만, 빛이 굴절되는 테두리와 라벨·뚜껑에서는 엣지가 뚜렷하게 생깁니다. 색 차이로 못 찾는 물체를 엣지로 찾는 방식입니다.
- **조건부로 두는 이유:** 엣지는 그림자 경계와 먼지에도 반응해 일반 물체에서는 색차 마스크보다 부정확합니다. 필요할 때만 씁니다.
- **그래도 실패하면:** 투입구 바로 아래 중앙의 고정 영역(사전에 측정한 정사각형)을 크롭합니다. 분류는 진행하되 신뢰도 임계값을 0.7로 높여 '확인 필요'로 더 쉽게 빠지게 합니다.
- **B-03 결과에 따른 변경:** 투명·반사 품목이 30% 이상이면 이 경로를 조건부가 아닌 기본 경로에 합치고(색차 마스크와 OR 결합), 배경을 회색 무광으로 바꾸는 실험을 합니다.

#### S9. 박스 확대·여백

- **기법:** 축소 해상도의 바운딩 박스를 4배로 키워 원본 좌표로 바꾸고, 사방으로 10% 여백을 줍니다. 화면 밖으로 나가면 화면 경계에서 자릅니다.
- **여백을 주는 이유:** 마스크는 투명한 가장자리나 연한 테두리를 놓치는 경우가 많습니다. 여백이 있어야 물체 전체가 크롭에 들어갑니다. 또 물체 외곽선 자체가 형태 단서이므로 배경이 조금 보여야 합니다.
- **마스크로 배경을 지우지 않는 이유:** 마스크가 틀렸을 때(투명 물체) 물체 일부가 잘려 나갑니다. 배경을 남겨 두고 모델이 스스로 물체를 보게 하는 편이 안전합니다. 배경이 항상 같은 흰색이므로 남겨 둬도 혼란이 적습니다 (P6).

#### S10. 원본 크롭 (+ 조건부 왜곡 보정)

- **기법:** 원본 1080p 이미지에서 박스 영역을 잘라냅니다. 렌즈 왜곡 보정이 필요하면(D-05), 미리 만든 remap 맵에서 같은 영역만 잘라 그 부분만 보정합니다.
- **원본에서 자르는 이유:** 코팅 종이컵의 광택, 페트병 표면의 미세한 질감은 저해상도에서는 사라집니다 (P2).
- **영역만 왜곡 보정하는 이유:** 전체 프레임을 보정하면 1080p 전체를 다시 계산해야 합니다. remap은 출력 픽셀마다 원본 위치를 찾아오는 방식이라, 출력 영역의 맵만 잘라 쓰면 결과가 같습니다 (P3).

#### S11. 흐림 검사

- **기법:** 크롭을 긴 변 256으로 줄인 회색조 이미지의 라플라시안 분산을 계산합니다.
- **초기 파라미터:** 분산 < 100이면 흐림으로 판단 (설치 후 선명한 샘플 50장의 분포를 보고 하위 5% 값으로 재설정).
- **크롭 후에 하는 이유:** 전체 화면으로 계산하면 넓은 흰 배경이 분산을 낮춰 물체가 선명해도 흐리다고 판단합니다. 물체 영역에서 재야 정확합니다.
- **S2와 따로 두는 이유:** 노출 검사는 전체 화면이 필요하고, 흐림 검사는 물체 영역이 필요해서 측정 대상이 다릅니다.
- **실패 시:** 시간 예산이 남아 있으면(누적 0.35초 이내) 1회 재촬영하고, 아니면 판정은 진행하되 신뢰도 임계값을 높입니다.

#### S12. 조명·색 보정

- **기법:** 크롭에 부팅 시 계산한 이득 맵의 같은 영역을 곱합니다 (채널별, float 연산 후 0~255로 자름).
- **적용 이유:** LED 스트립은 가운데가 밝고 가장자리가 어두우며, LED마다 색온도가 조금씩 다릅니다. 같은 캔도 가장자리에 놓이면 더 어둡고 노랗게 찍힙니다. 이득 맵은 이 위치별 차이를 없애 물체가 어디에 놓여도 같은 색으로 보이게 합니다.
- **한 번의 곱셈으로 두 가지를 하는 이유:** 이득 맵은 채널별로 계산되므로, 조명 불균일(평탄화 보정)과 색 틀어짐(화이트밸런스)이 한 번에 보정됩니다. 매번 회색 기준판을 측정할 필요가 없습니다.
- **크롭 후에 하는 이유:** 픽셀별 곱셈은 이웃 픽셀과 무관하므로 크롭 전후 결과가 같고, 크롭 후에 하면 계산량이 크게 줄어듭니다 (P3).
- **리사이즈 전에 하는 이유:** 이득 맵은 원본 해상도 기준이라, 리사이즈 후에는 위치가 맞지 않습니다.
- **배경 차분에는 왜 안 쓰는가:** 저장 배경과 실시간 입력이 같은 조명 분포를 가지므로 차분에서는 조명 불균일이 자동으로 상쇄됩니다. 보정이 필요한 것은 분류 모델이 보는 색입니다.

#### S13. 정사각형 패딩 + 224 리사이즈

- **기법:** 크롭의 짧은 변 쪽을 배경 평균색으로 채워 정사각형으로 만든 뒤, INTER_AREA로 224×224로 줄입니다.
- **늘리지 않고 패딩하는 이유:** 페트병처럼 긴 물체를 정사각형으로 늘리면 형태가 찌그러져, 모델이 '길쭉함'이라는 형태 단서를 잃습니다.
- **배경색으로 채우는 이유:** 검은색으로 채우면 물체 옆에 실제로 없는 강한 경계가 생기고, 학습 데이터(배경 합성 이미지)와 모양이 달라집니다 (P5).
- **패딩을 리사이즈보다 먼저 하는 이유:** 리사이즈 후 패딩하면 짧은 변 길이 계산을 두 번 해야 하고, 보간 경계에 미세한 띠가 생길 수 있습니다.
- **작은 물체 주의 (B-07):** 크롭이 224보다 작으면 확대가 되므로 INTER_LINEAR로 바꿉니다. 이런 경우가 많으면 카메라를 더 가까이 두는 것을 검토합니다 (D-06).

#### S14. 정규화·형식 변환

- **기법:** GPU로 올린 뒤 BGR → RGB, 0~1 스케일, ImageNet 평균·표준편차 정규화, HWC → CHW, FP16 변환.
- **적용 이유:** 사전학습 가중치가 ImageNet 기준으로 정규화된 입력을 가정합니다.
- **맨 마지막인 이유:** 정규화는 "모델과의 약속"입니다. 앞 단계의 모든 처리는 사람이 눈으로 확인할 수 있는 이미지 상태에서 하고, 모델 입력 형식으로 바꾸는 것은 끝에 한 번만 합니다. 로그에는 S13 결과(224 이미지)를 저장해 검수에 씁니다.
- **GPU에서 하는 이유:** 어차피 TensorRT 입력은 GPU 메모리에 있어야 하므로, 업로드 직후 GPU에서 변환하면 CPU-GPU 복사가 한 번으로 끝납니다.

## 7. 운영 중 배경 유지 관리

라이트박스 배경은 시간이 지나면서 바뀝니다. LED 노화, 바닥에 쌓이는 먼지와 얼룩, 낮밤의 미세한 외부광 차이(A-03) 때문입니다. 배경이 바뀌면 S4 차분에 물체가 없는 영역도 잡히기 시작합니다.

| 상황 | 감지 방법 | 처리 |
|---|---|---|
| 서서히 변하는 배경 | 물체가 없는 대기 상태 | 10분마다 투입 센서가 꺼져 있고 차이가 작을 때 `새 배경 = 0.95 × 기존 + 0.05 × 현재`로 갱신 |
| 갑자기 변한 배경 (얼룩, 물방울) | 대기 상태 프레임의 차분 마스크 면적 > 1% | 자동 갱신하지 않고 청소 알림 (얼룩을 배경으로 학습하면 같은 위치의 물체를 놓친다) |
| 조명 밝기 변화 | 대기 상태 평균 밝기가 기준 대비 ±10% | 배경 재촬영 + 이득 맵 재계산 |

**갱신 시 이득 맵도 바꾸지 않는 이유.** 이득 맵은 조명 분포를 나타내므로 먼지 같은 작은 변화로 다시 계산하면 오히려 흔들립니다. 조명 자체가 바뀌었을 때만 다시 계산합니다.

## 8. 적용하지 않는 기법과 이유

흔히 쓰이지만 에코소트 환경에는 맞지 않아 기본 파이프라인에서 뺀 기법입니다.

| 기법 | 빼는 이유 | 다시 검토할 조건 |
|---|---|---|
| CLAHE·히스토그램 평활화 | 고정 조명에서는 이미 대비가 일정하다. 이미지마다 밝기·색 분포를 다르게 바꿔 투명 페트와 흰 종이 같은 미묘한 차이를 오히려 흐린다 (P6) | 렌즈 결로로 대비가 떨어질 때 (A-04) |
| 그레이스케일 변환 | 색이 투명 페트와 유색 플라스틱, 캔 종류를 구분하는 핵심 단서다 (P6) | 없음 |
| 비지역 평균(NLM) 디노이징 | 1080p 크롭에서 수십~수백 ms가 걸려 예산을 넘는다. 고정 조명·적정 노출에서는 잡음이 크지 않다 | 저조도로 노출을 크게 올려야 할 때 |
| 샤프닝 | 압축 잡음까지 강조해 학습 데이터와 분포가 달라진다 | 없음 |
| 하이라이트 인페인팅 | 수 ms 이상 걸리고, 지워진 영역을 그럴듯하게 채워 넣어 오히려 가짜 질감을 만든다. 하이라이트 자체가 '금속·플라스틱'의 단서이기도 하다 | 없음 (노출 하향과 편광 필름으로 대응) |
| 배경 지우기 (마스크 밖을 단색으로) | 마스크가 틀리면 물체 일부가 사라진다 (S9 참고) | 마스크 IoU가 0.95 이상으로 안정될 때 E9로 비교 |
| 고정 크기 중앙 크롭 | 물체 위치·크기 편차가 커서 작은 물체는 배경만, 큰 물체는 잘린다 | 대체 경로로만 사용 (S8) |

## 9. 학습용 오프라인 전처리

### 9-1. 원칙: 학습 데이터도 같은 전처리 함수를 통과한다

학습 데이터와 실시간 입력이 서로 다른 코드로 처리되면, 실험에서는 정확도가 높은데 장치에서는 낮게 나옵니다 (P5). 그래서 S1~S13을 하나의 파이썬 모듈로 만들고, 학습 데이터 준비와 장치 추론에서 **같은 모듈을 import**합니다.

또 장치에서는 **원본 프레임과 S13 결과를 모두 저장**합니다. 나중에 전처리를 바꿔도 원본에서 다시 처리할 수 있어야 데이터를 버리지 않습니다.

### 9-2. 데이터 출처별 처리 순서

| 출처 | 처리 순서 | 이유 |
|---|---|---|
| 자체 촬영 | 원본 프레임 → S1~S13 그대로 | 실제 입력과 완전히 같음 |
| TACO (분할 마스크 있음) | 마스크로 물체 오려내기 → 빈 배경 30장 중 하나에 합성 → 합성 그림자 추가 → S1~S13 | 실외 배경을 에코소트 배경으로 바꿔 배경 차이를 없앰 |
| TrashNet (단순 배경) | GrabCut으로 물체 오려내기 → 위와 같이 합성 → S1~S13 | 배경은 단순하지만 조명·색이 달라 그대로 쓰면 도메인 차이가 큼 |
| AI Hub | 바운딩 박스로 크롭 → 마스크가 있으면 합성, 없으면 GrabCut → S1~S13 | 위와 같음 |

**합성 시 세부 처리**

- **크기:** 실제 촬영에서 측정한 물체 크기 분포(B-07, D-06)에 맞춰 무작위로 정합니다. 공개 데이터의 원래 크기를 그대로 쓰면 에코소트에서 볼 수 없는 크기가 섞입니다.
- **위치:** 투입구 아래 물체가 떨어지는 범위 안에서 무작위로 정합니다.
- **경계:** 마스크 경계를 2~3픽셀 흐려 붙입니다. 경계가 칼로 자른 듯 선명하면 모델이 '합성 흔적'을 단서로 배울 수 있습니다.
- **그림자:** 물체 마스크를 아래쪽으로 조금 밀고 흐린 뒤 배경을 10~20% 어둡게 해서 접지 그림자를 만듭니다 (D-02의 실제 그림자 형태 참고).
- **색 맞춤 (E4에서 효과 확인):** 합성한 물체의 Lab 평균·표준편차를 자체 촬영 데이터의 같은 클래스 분포에 가깝게 맞춥니다 (Reinhard 색 전이 방식).

### 9-3. 증강 순서와 근거

증강은 S13 결과(224) 대신 **S12 결과를 긴 변 256으로 패딩·리사이즈한 이미지**에 적용한 뒤, 마지막에 224로 랜덤 크롭합니다. 여유 픽셀이 있어야 회전·크롭 증강 시 물체가 잘리지 않습니다.

| 순서 | 증강 | 범위 | 확률 | 순서 근거 |
|---|---|---|---|---|
| 1 | 회전 | 0~360°, 빈 영역은 배경 평균색 | 1.0 | 형태 변환을 먼저 해야 이후 색 변화가 회전으로 생긴 빈 영역에도 고르게 적용된다 |
| 2 | 좌우·상하 반전 | | 0.5 | |
| 3 | 탄성 변형·격자 왜곡 | 약~중 (B-06 결과로 조정) | 0.3 | 구김 재현. 기하 변환끼리 묶어 보간을 최소화 |
| 4 | 랜덤 크롭 224 | 원본의 85~100% 후 224 | 1.0 | 크롭 오차 재현. 기하 변환의 마지막 |
| 5 | 부분 가림 (CoarseDropout) | 크기 5~15%, 1~3개, 채움색은 배경색 또는 라벨 색 무작위 | 0.3 | 라벨 제거·얼룩 재현. 최종 크기가 정해진 뒤 크기를 지정해야 일정하다 |
| 6 | 밝기·대비 | ±10% | 0.5 | 조명 미세 변화. 고정 조명이라 범위를 좁게 둔다 |
| 7 | 색조·채도 | 색조 ±5, 채도 ±10% (F-02 별도 배출이면 색조 ±2) | 0.3 | 색 단서 보존을 위해 약하게 (P6) |
| 8 | 가우시안 블러 | 커널 3~5 | 0.1 | S0·S11을 통과한 약한 흐림 재현 |
| 9 | JPEG 압축 | 품질 70~95 | 0.3 | MJPEG 압축 잡음 재현. 실제 장치 입력과 맞춤 |
| 10 | 정규화 | ImageNet 기준 | 1.0 | S14와 동일 (P5) |

**밝기·색 증강을 약하게 두는 이유.** 일반적인 이미지 분류에서는 밝기·색 증강을 강하게 하지만, 에코소트는 조명이 고정되고 S12에서 색이 보정됩니다. 강한 색 증강은 실제로 존재하지 않는 입력을 만들고, 색으로 구분해야 하는 클래스(투명 페트 vs 유색 플라스틱)를 헷갈리게 합니다.

**검증·테스트 데이터에는 증강을 쓰지 않습니다.** 256 → 224 중앙 크롭만 적용합니다.

## 12. 참고 구현 (뼈대 코드)

실제 구현의 출발점이 되는 구조입니다. 파라미터는 위 설계의 초기값이며, 실험 결과로 바꿉니다.

```python
import cv2
import numpy as np

SCALE = 4            # S1 축소 배율
W_L = 0.5            # S4 밝기 가중치
THRESH = 20          # S5 이진화 임계값
MIN_AREA = 0.005     # S7 최소 면적 비율
MARGIN = 0.10        # S9 여백
TARGET = 235.0       # 4장 이득 맵 목표값


class EcoPreprocessor:
    def __init__(self, bg_frames):
        """부팅 시 캘리브레이션: 빈 라이트박스 프레임 10장을 받는다."""
        bg = np.mean(np.stack(bg_frames).astype(np.float32), axis=0)
        bg_u8 = bg.astype(np.uint8)

        small = cv2.resize(bg_u8, None, fx=1 / SCALE, fy=1 / SCALE,
                           interpolation=cv2.INTER_AREA)
        self.bg_lab = cv2.cvtColor(cv2.GaussianBlur(small, (3, 3), 0),
                                   cv2.COLOR_BGR2LAB).astype(np.int16)
        self.bg_edge = self._edge(small)

        illum = cv2.GaussianBlur(bg, (0, 0), sigmaX=25)
        self.gain = (TARGET / np.maximum(illum, 1.0)).astype(np.float32)
        self.bg_mean = np.clip(bg * self.gain, 0, 255).mean(axis=(0, 1))
        self.pad_color = tuple(int(v) for v in self.bg_mean)
        self.bg_brightness = small.mean()

    @staticmethod
    def _edge(img_bgr):
        gray = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2GRAY)
        gx = cv2.Sobel(gray, cv2.CV_32F, 1, 0, ksize=3)
        gy = cv2.Sobel(gray, cv2.CV_32F, 0, 1, ksize=3)
        return cv2.magnitude(gx, gy)

    def process(self, frame):
        """S1~S13. (224 이미지 또는 None, 상태 문자열)을 반환한다."""
        h, w = frame.shape[:2]

        # S1 축소
        small = cv2.resize(frame, None, fx=1 / SCALE, fy=1 / SCALE,
                           interpolation=cv2.INTER_AREA)

        # S2 노출 검사
        mean = small.mean()
        if abs(mean - self.bg_brightness) > 0.25 * self.bg_brightness:
            return None, "light_error"
        saturated = (small.max(axis=2) >= 250).mean() > 0.05

        # S3 블러 + Lab
        lab = cv2.cvtColor(cv2.GaussianBlur(small, (3, 3), 0),
                           cv2.COLOR_BGR2LAB).astype(np.int16)

        # S4 가중 색차 배경 차분
        d = np.abs(lab - self.bg_lab).astype(np.float32)
        diff = np.maximum(W_L * d[..., 0], np.maximum(d[..., 1], d[..., 2]))

        # S5 이진화
        mask = (diff > THRESH).astype(np.uint8) * 255

        # S6 모폴로지: 열림(잡음 제거) -> 닫힘(구멍 메우기)
        mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN, np.ones((3, 3), np.uint8))
        mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, np.ones((7, 7), np.uint8))

        # S7 컨투어 선택
        box, status = self._select(mask, small.shape)

        # S8 투명 물체 대체 마스크
        if box is None:
            edge = np.clip(self._edge(small) - self.bg_edge, 0, None)
            emask = (edge > 40).astype(np.uint8) * 255
            emask = cv2.morphologyEx(emask, cv2.MORPH_CLOSE,
                                     np.ones((9, 9), np.uint8))
            box, status = self._select(emask, small.shape)
            if box is None:
                return None, "no_object"
            status = "edge_fallback"
        elif status == "multi":
            return None, "multi_object"

        # S9 박스 확대 + 여백
        x, y, bw, bh = [v * SCALE for v in box]
        mx, my = int(bw * MARGIN), int(bh * MARGIN)
        x0, y0 = max(x - mx, 0), max(y - my, 0)
        x1, y1 = min(x + bw + mx, w), min(y + bh + my, h)

        # S10 원본 크롭
        crop = frame[y0:y1, x0:x1]

        # S11 흐림 검사
        probe = cv2.resize(crop, (256, int(256 * crop.shape[0] / crop.shape[1])))
        sharp = cv2.Laplacian(cv2.cvtColor(probe, cv2.COLOR_BGR2GRAY),
                              cv2.CV_64F).var()
        if sharp < 100:
            status += "|blurry"

        # S12 조명·색 보정 (이득 맵의 같은 영역을 곱함)
        crop = np.clip(crop.astype(np.float32) * self.gain[y0:y1, x0:x1],
                       0, 255).astype(np.uint8)

        # S13 정사각형 패딩(배경색) + 224 리사이즈
        ch, cw = crop.shape[:2]
        side = max(ch, cw)
        top, left = (side - ch) // 2, (side - cw) // 2
        crop = cv2.copyMakeBorder(crop, top, side - ch - top, left,
                                  side - cw - left, cv2.BORDER_CONSTANT,
                                  value=self.pad_color)
        interp = cv2.INTER_AREA if side >= 224 else cv2.INTER_LINEAR
        out = cv2.resize(crop, (224, 224), interpolation=interp)

        if saturated:
            status += "|saturated"
        return out, status or "ok"

    @staticmethod
    def _select(mask, shape):
        contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL,
                                       cv2.CHAIN_APPROX_SIMPLE)
        min_px = MIN_AREA * shape[0] * shape[1]
        areas = sorted([(cv2.contourArea(c), c) for c in contours
                        if cv2.contourArea(c) >= min_px],
                       key=lambda t: t[0], reverse=True)
        if not areas:
            return None, ""
        if len(areas) > 1 and areas[1][0] >= 0.3 * areas[0][0]:
            return cv2.boundingRect(areas[0][1]), "multi"
        return cv2.boundingRect(areas[0][1]), ""
```

**코드 사용 시 참고**

- S0(정지 감지 촬영)과 S14(GPU 정규화)는 카메라 제어부와 TensorRT 추론부에 들어가므로 이 클래스에서는 뺐습니다.
- 같은 `EcoPreprocessor.process()`를 학습 데이터 준비 스크립트에서도 그대로 호출합니다 (P5). 학습용은 마지막 리사이즈 크기만 256으로 바꿔 증강 여유를 둡니다.
- 렌즈 왜곡 보정(S10 조건부)은 D-05 결과에 따라 `cv2.initUndistortRectifyMap`으로 만든 맵을 크롭 영역만 잘라 `cv2.remap`에 넣는 방식으로 추가합니다.
- 실측 시간은 `time.perf_counter()`로 단계마다 기록해 H-03 항목에 적습니다.
